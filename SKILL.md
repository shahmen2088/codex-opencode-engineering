# Codex/OpenCode engineering

1. Сначала прочитать `AGENTS.md`, `CLAUDE.md`, локальные правила и состояние Git.
2. Разделить задачу на наблюдение, план, изменение и проверку. Не менять файлы до фиксации границ задачи.
3. Найти существующий код и тесты через быстрый поиск; не создавать новый слой, если уже есть подходящий.
4. Перед изменением описать контракт: входы, выходы, ошибки, побочные эффекты и способ проверки.
5. Делать минимальный патч, сохранять обратную совместимость и не трогать секреты, `.env` и пользовательские данные.
6. После правки запустить узкие тесты, затем релевантный полный набор. Для UI проверить браузерный smoke-тест.
7. Сформировать итог: изменённые файлы, проверенные команды, оставшиеся риски и следующий шаг. Push, deploy и удаление требуют отдельного явного разрешения.

Если задача расплывчата, сначала подготовить короткий план и список неизвестных. Если обнаружен сбой теста, сначала установить причину, а не маскировать симптом.

## Пример

Запрос: «добавь импорт прайсов».

Сначала найти текущий ingestion pipeline и формат эталонных данных, затем предложить контракт импорта и тест на дубликат/неизвестную колонку. Только после этого редактировать код.
